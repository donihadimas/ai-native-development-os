# Release: 0.6.0 (Enterprise Rules Upgrade)

## Scope

- Included: Injection of 21 Comprehensive Enterprise Rules into AIOS master templates (`references/` and `prompts/`). Fixing flaky CLI unit test. Version bump to 0.6.0.
- Excluded: Feature additions to the CLI itself.

## User-Visible Changes

- Newly adopted projects (`aios adopt` atau `aios create new`) will now strictly adhere to advanced architectural constraints (SOLID, Layer Separation).
- Code generated will inherently prevent N+1 queries, mandate paginated database responses, and enforce Server-side Rendering leakage protections.

## Developer-Visible Changes

- `engineering-principles.md`, `frontend-principles.md`, `backend-principles.md`, `backend-api-standards.md`, `database-standards.md`, `security-principles.md`, and `testing-principles.md` have been hardened.
- `06-implement-task.md` now enforces a strict Definition of Done (DoD).
- `07-review-code.md` now features an 11-point Self-Review Checklist.

## Validation Evidence

- Tests: 79 passing, 0 failing in `cli/test/commands.test.ts`.
- Review: Analyzed and approved by the user during the planning phase.
- Manual checks: Verified the contents of all generated markdown templates.

## Deployment or Publish Checklist

- [x] Version confirmed (0.6.0).
- [x] Tests passed.
- [x] Package or build dry-run completed.
- [x] Documentation updated (`CHANGELOG.md`).
- [x] Human approval recorded.

## Rollback Plan

- If developers find the new rules too restrictive for lite projects, we can revert the commits inside the `references/` directory, bump to 0.6.1, and republish.

## Post-Release Checks

- Verify that `npx @donihadimas/aios@0.6.0 init <project>` successfully pulls down the new rules.

## Known Risks and Follow-Up

- Projects using older frameworks may struggle with the stringent React Server Component rules unless correctly scoped using `.aios/config.json`.
