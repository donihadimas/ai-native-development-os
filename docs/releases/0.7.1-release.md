# Release: 0.7.1 (Legacy Kit Cleanup & Asset Pruning Patch)

## Scope

- Included: Full unmanaged/legacy asset cleanup in `aios update --clean`, deletion of deprecated `.aios/commands/` and `.aios/prompts/`, native mode `.aios/skills/` cleanup, tracking of removed items in `AdoptResult`, and comprehensive integration tests.
- Excluded: New CLI commands or schema breaking changes.

## User-Visible Changes

- **Automatic Legacy Asset Pruning**: Running `aios update --clean` now automatically cleans up unmanaged and deprecated top-level directories in `.aios/` (such as `.aios/commands/` and `.aios/prompts/`), leaving only active workflow kit assets (`workflows`, `templates`, `references`, `integrations`, `skill-router.md`) and runtime files.
- **Native Delivery Pruning**: When using `native` skill delivery mode, `aios update --clean` purges obsolete portable `.aios/skills/` while retaining agent-native skills in `.agents/skills/`.
- **Informative Cleanup Logs**: Clear output messages showing removed legacy items (`Clean: removed deprecated/unmanaged kit entry: .aios/...`).

## Developer-Visible Changes

- **`AdoptResult` Extension**: Extended `AdoptResult` in `cli/src/core.ts` with optional `removed?: string[]` to trace deleted assets.
- **Enhanced `cleanExtraEntries`**: Recursive cleanup function now records deleted paths for verification and logging.
- **Protected Runtime Files**: Explicit allowlist ensures project state files (`config.json`, `repo-map.json`, `worktrees/`, `telemetry.json`, `.gitkeep`, `.gitignore`) and user tasks in `docs/tasks/` are never deleted during cleanup.

## Validation Evidence

- **Tests**: 107 passing, 0 failing across all unit and command integration tests (`npm --prefix cli test`).
- **Review**: Validated against `AGENTS.md` and `prd.md` core layer architecture.
- **Manual Checks**: Verified clean execution against local workspace and test project environments.
